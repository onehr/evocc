# E3012: misaligned-memory-access

The pointer is not aligned for the executed access.
A cast changes the pointer type but does not align the address.

C typed accesses must meet the required alignment.
Use aligned storage or copy bytes into an aligned object before a typed read.

```c,E3012
int main(void) {
    int values[2] = {0};
    char *p = (char *)values;
    return *(int *)(p + 1);
}
```

```c,fixed
int main(void) { int values[2] = {0}; return values[1]; }
```

EvoCC judges alignment by the object's declared alignment and the offset into the object
(EvoIR 5.4), not by the address that a native build happens to use. So a pointer that the program
aligns by integer arithmetic on its address, or a wide access that relies on the compiler placing
an array on a stronger boundary than its type needs, is reported here even when the native
address is aligned. Declare the alignment that the access needs, for example
`_Alignas(16) float buffer[64];`, so that the model can see it.
