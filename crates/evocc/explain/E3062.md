# E3062: invalid-atomic-access

An IR or interpreter atomic access violates its type, width, alignment, or order contract.
This is distinct from a valid atomic operation applied to a null or dangling pointer.

Atomic accesses require specific access sizes and legal ordering combinations.
The validator and memory implementation check that contract before performing the operation.

Trigger: none
Reason: the C front end rejects unsupported atomic forms before this internal access check.

C operand and order errors report E2913 or E2947.
Ordinary pointer faults retain their memory diagnostic codes.
