# E2940: unsupported-scalar-storage-order

The source requests a scalar storage order that EvoCC does not implement.
This attribute can change the byte order of record members.

Ignoring it would change the program's object representation.
Use explicit byte encoding when a data format needs a particular byte order.

```c,E2940
struct __attribute__((scalar_storage_order("big-endian"))) S { unsigned x; };
int main(void) { return 0; }
```

```c,fixed
int main(void) {
    unsigned x = 258;
    unsigned char bytes[2] = {(unsigned char)(x >> 8), (unsigned char)x};
    return bytes[0] != 1 || bytes[1] != 2;
}
```

The fixed example encodes a two-byte field explicitly; it does not recreate the struct ABI.
